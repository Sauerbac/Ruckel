# v2 — Single copyable binary: FFmpeg linked in-process

Came out of a full grilling pass on 2026-06-09, walked branch-by-branch to shared
understanding. v1 is feature-complete and tagged **`v1.0-sidecar`**; this work happens on the
**`v2`** branch. This PRD is the detailed record of every decision plus the implementation
plan. The architecture decisions live in **ADR-0027 … ADR-0031**; this document adds the
implementation-level detail that doesn't belong in ADRs.

## The goal

`ruckel.exe`, alone, is the product. Copy it to a USB stick, run it on the presentation
laptop. No sidecars, no installer, no files beside it. FFmpeg and ffprobe functionality is
compiled **into** the executable — only the exact functionality the app needs; everything
else is bloat and stays out.

**Strictly an architecture swap with zero behavior change.** No FFmpeg-version adventures
beyond pinning the same n7.1.x series, no x264 tuning changes, no new options, no frontend
changes. If the app behaves differently afterwards (beyond "unsupported exotic file is now
skipped"), that's a bug.

## Decision trail (the grilled questions, in dependency order)

| # | Question | Decision |
|---|---|---|
| Q1 | One-file-to-copy vs. FFmpeg-in-process? | **In-process is the goal itself**, not merely the means. Embed-and-extract rejected. (ADR-0027) |
| Q2 | fftools-in-process vs. libav\* API? | **libav\* API directly**; custom transcode loop; ffprobe split dissolves. (ADR-0027) |
| Q3 | Bindings: bindgen / sys-crate / safe wrapper? | **rsmpeg** (safe wrapper, bring-your-own static FFmpeg). Tracer-bullet link test gates everything. (ADR-0027) |
| Q4 | How far does input support shrink? | **Curated decode matrix**, ADR-documented, enforced by fixtures. **AV1 via dav1d is in.** Exotic tail dropped → pre-flight skip + notice (ADR-0026 machinery). (ADR-0028) |
| Q5 | Build toolchain? | **MSYS2 shell + MSVC (`cl.exe`)**: FFmpeg `--toolchain=msvc`, x264 `CC=cl`, dav1d meson/MSVC. Manifest-pinned sources + flags, committed script. (ADR-0029) |
| Q6 | Where do libs get built? | **On this machine** for the foreseeable future; contract kept CI-shaped for later. Libs gitignored, manifest-hash guard in `build.rs`. (ADR-0029) |
| Q7 | Shipped artifact? | **Bare `ruckel.exe`**; WebView2-evergreen assumed present (as v1 already does). No installer. (ADR-0030) |
| Q8 | Runtime model? | **Frontend contract frozen byte-for-byte.** Worker thread per job, `AtomicBool` cancel per packet, PTS-derived progress at ~500 ms, in-process probe behind unchanged `ProbeResult`. Crash blast radius accepted. (ADR-0031) |
| Q9 | How do we prove the matrix? | Pure `options → EncoderConfig` seam with table tests; **committed fixture corpus** generated by the old sidecar; **manifest↔corpus drift test**; structural output assertions incl. real faststart check; one human PowerPoint sanity check per release. |
| Q10 | Sequencing? | Tag → fixtures-first → libs → tracer gate → probe swap → encoder swap → matrix tests → retire sidecars → docs. Riskiest unknown first; everything needing the old sidecar before its retirement. |

## Architecture: the transcode loop

One Conversion Job = one worker thread running:

```
open input (avformat_open_input, find_stream_info)
select best video stream + best audio stream (if any, and audio option != None)
decoders: avcodec per stream
video filter graph (libavfilter, minimal build):
    buffer → [transpose/hflip/vflip if display-matrix says so]
           → [scale=-2:H if resolution cap]      (even width, aspect preserved)
           → format=yuv420p                       (always — normalizes 10-bit/4:2:2/etc.)
           → [fps=N if framerate cap]             (CFR drop/duplicate, CLI -r parity)
           → buffersink
audio path (no avfilter): swresample → fltp + an AAC-supported sample rate,
    channel layout preserved (CLI parity)
encoders: libx264 (profile=high, preset=medium, crf=<option>, NO level — x264 derives it)
          native aac (b=<option>) | no audio stream at all if option == None
mux: mp4 muxer, movflags=+faststart, writing to the ADR-0012 temp path
loop: read packet → (cancel check) → decode → filter → encode → rescale ts → interleaved write
      progress = muxed video PTS / probed duration, emitted ≤ every 500 ms
drain: flush decoders, filter graph, encoders, write trailer
finish: atomic rename temp → _ppt output (ADR-0012, unchanged)
```

Implementation notes (the unglamorous parity details):

- **Autorotation:** read the display-matrix side data (`av_display_rotation_get`) from the
  video stream; map 90/180/270 (+flips) to `transpose`/`hflip`/`vflip` filters; do **not**
  copy the matrix to the output. This matches the ffmpeg CLI's default `-autorotate`.
  Discovered during write-up; recorded as a flagged refinement in ADR-0027 (we'd leaned
  swscale-only — rotation + CFR made minimal avfilter the cleaner equivalent).
- **Framerate cap:** the `fps` filter reproduces `-r` output semantics (drop/duplicate to
  CFR). Without a cap, no `fps` filter — source timing passes through, as today.
- **AAC input constraints:** native `aac` wants `fltp` and a supported sample rate;
  `swresample` converts. Preserve source channel layout and sample rate when supported,
  resample to nearest supported rate when not (CLI parity).
- **Faststart:** the mp4 muxer's `+faststart` does its moov-relocation rewrite on
  `av_write_trailer` against the **temp** file — fully compatible with temp+rename.
- **`+faststart` is verified structurally in tests** (`moov` byte-offset before `mdat`) —
  something the v1 suite never actually checked.
- **Progress source:** video packet PTS at mux time (rescaled to seconds) over probed
  duration, clamped to [0, 1]. Audio-only progress doesn't exist (no video → pre-flight
  rejected it already).
- **Cancel:** check the job's `AtomicBool` once per demuxed packet; on cancel, drop all
  contexts (rsmpeg RAII), delete temp, emit the existing cancelled event.

## The build pipeline (`scripts/build-ffmpeg/`)

Committed manifest `src-tauri/ffmpeg-build-manifest.json` pins:

- **FFmpeg n7.1.x** source tarball (same major as the v1 sidecar, rsmpeg-supported) + SHA-256
- **x264** (stable branch commit) + SHA-256
- **dav1d** (latest release) + SHA-256
- the **full configure flag sets** for all three — the FFmpeg flags are the ADR-0028 matrix:
  `--disable-everything --disable-network --disable-avdevice --disable-doc
  --disable-programs --enable-gpl --toolchain=msvc --enable-static --disable-shared
  --enable-libx264 --enable-libdav1d --enable-encoder=libx264,aac --enable-muxer=mp4
  --enable-protocol=file --enable-demuxer=… --enable-decoder=… --enable-parser=…
  --enable-filter=buffer,buffersink,scale,format,transpose,hflip,vflip,fps,null`
  (exact enumerations per the ADR-0028 tables; the manifest is the mechanical source of truth)

Script responsibilities: verify tool prerequisites (MSYS2, VS Build Tools env, meson, ninja,
nasm), download + SHA-verify tarballs, build dav1d → x264 → FFmpeg in dependency order,
install static libs + headers + `.pc` files into gitignored `src-tauri/ffmpeg-libs/`, and
write a `manifest-hash` stamp file there. `build.rs` fails the cargo build loudly if the
stamp doesn't match the committed manifest (stale-build guard).

**Known-finicky items, resolved empirically by the tracer slice (step 4):**

- rusty_ffmpeg discovery mechanism: pkg-config path vs. explicit include/libs env vars.
- The Windows system libs FFmpeg's pkg-config demands with everything disabled
  (`bcrypt` for RNG; possibly `ole32`/`user32`) — whatever the tracer proves goes in the
  manifest notes and `build.rs`.
- MSVC static-lib naming (`.a` vs `.lib`) as emitted by FFmpeg's msvc toolchain mode.
- CRT selection consistency (`/MT` vs `/MD`) between the three libs and Rust's msvc target
  defaults.

## Testing strategy

1. **Pure seam:** `options → EncoderConfig` table tests replace the `args.rs` flag-pair
   tests; same coverage philosophy (every preset + every knob), now asserting the struct.
   ADR-0006's contract (h264 high, yuv420p, no level, faststart, aac/an) asserted here.
2. **Fixture corpus** (committed, generated **once** by the v1 sidecar before it's retired):
   ~1 s, 64×64, silent-tone audio, one per real-world (demuxer × vcodec × acodec) cell —
   h264+aac/mp4, hevc+aac/mp4 & mkv, av1+opus/mp4 (libaom/svtav1 from the old sidecar),
   vp9+opus/webm, vp8+vorbis/webm, mpeg4+mp3/avi, msmpeg4v3+wmav2/asf, wmv2+wmav2/asf,
   mpeg2+mp2/ts, mpeg2+ac3/vob, mpeg1/mpegvideo, prores+pcm_s16le/mov, dnxhd/mxf,
   mjpeg+pcm/avi, theora+vorbis/mkv, h263/3gp(mov), flv1+mp3/flv, flac/alac/eac3 audio
   variants, plus a rotated (display-matrix) h264/mp4 and an extensionless copy for the
   ADR-0011 path. A few KB each, low hundreds of KB total, committed directly (no LFS).
   - **Known un-generatable cells:** FFmpeg has no `vc1`/`wmv3` or `wmapro` encoder. These
     two get an **allowlisted gap** in the drift test (decoder enabled, no fixture);
     optionally later: pin an external sample by SHA-256. Recorded, not forgotten.
3. **Matrix drift test:** enumerate decoders/demuxers from the committed build manifest and
   assert a fixture (or allowlisted gap) exists for each — manifest and corpus cannot drift
   apart silently.
4. **Integration tests (in-process):** probe + transcode every fixture; assert output opens,
   is h264 high + aac (or no audio), yuv420p, even dimensions, sane duration, and `moov`
   precedes `mdat`. The rotated fixture asserts physical rotation (dimensions swapped).
5. **Human check, once per release:** drop an output into actual PowerPoint.

## Sequencing (the gates are load-bearing)

1. ✅ **Tag `v1.0-sidecar`**, branch **`v2`**. (Done 2026-06-09.)
2. **Fixture corpus** — generation script runs against the still-present v1 sidecar; corpus
   committed. *Must precede sidecar retirement.*
3. **Build the libs** — manifest + `scripts/build-ffmpeg/`, run locally; gitignored
   `ffmpeg-libs/` populated; stale-build guard wired in `build.rs`.
4. **THE TRACER GATE** — standalone `cargo test`: rsmpeg links against our libs and
   transcodes one h264 fixture in-process on `x86_64-pc-windows-msvc`. **Nothing else
   proceeds until green.** Retires the MSVC-link, rsmpeg-discovery, and disable-everything
   risks in one place, before any production code is touched.
5. **Probe swap** — `probe.rs` goes in-process behind the unchanged `ProbeResult`; ffprobe
   sidecar retired. Independently mergeable (interim hybrid: in-process probe + sidecar
   encode is fine).
6. **Encoder swap** — `EncoderConfig` seam + transcode loop + progress/cancel behind the
   frozen ADR-0016 contract. The big slice.
7. **Matrix integration tests** wired to the manifest (drift test + per-fixture transcode).
8. **Retire the sidecar machinery** — `externalBin` + `bundle.android` from
   `tauri.conf.json`, `src-tauri/binaries/`, `scripts/fetch-ffmpeg.mjs`,
   `ffmpeg-manifest.json`, `sidecar_command` in `lib.rs`, old `smoke.rs`. Add dav1d's
   BSD-2 license text to the shipped GPL notices.
9. **Docs close-out** — CONTEXT.md: **Sidecar** leaves the glossary, **Probe** redefined
   (in-process libavformat read), stack line "FFmpeg + ffprobe, bundled as sidecar
   processes" rewritten, **PowerPoint-safe flags** reworded from flag-vector to encode
   contract. (ADRs 0027–0031 already written, 2026-06-09.)

Each slice lands as its own merge to `v2`; no mega-branch. Two orderings are non-negotiable:
fixtures before sidecar retirement, and the tracer gate before either swap.

## Explicitly out of scope

- Any frontend change whatsoever (contract frozen, ADR-0016/0031).
- New user options, x264 tuning changes, preset changes (ADR-0006/0007 untouched).
- Parallel encoding (ADR-0009 stays sequential).
- CI — deferred; manifest/script contract is already CI-shaped (ADR-0029).
- Installer / WebView2 bundling (ADR-0030).
- Long-tail codec support beyond the matrix (ADR-0028; growing it later is a manifest edit).

## Risks & accepted tradeoffs

- **Crash blast radius** — libav access violation kills the app, not a child. Accepted;
  rationale in ADR-0027; temp+rename means no corrupt outputs ever.
- **MSVC link finickiness** — the single biggest unknown; deliberately front-loaded into the
  step-4 tracer gate. Fallback if rsmpeg specifically misbehaves: its `rusty_ffmpeg` sys
  layer (contained refactor).
- **Behavior-parity subtleties** — autorotation, CFR cap semantics, AAC resampling edge
  cases, 10-bit→8-bit conversion. Each has an explicit fixture or implementation note above;
  the fixture suite is the regression net.
- **Regression on exotic v1-convertible files** — deliberate, ADR-0028; user sees the
  existing skip-with-notice flow (ADR-0026).
